# DDD中的战略设计与战术设计

## 战略设计(Strategic Design)

战略设计关注的是系统的整体结构和组织方式，主要解决"系统是什么"和"系统如何划分"的问题：

1. **限界上下文(Bounded Context)**
   - 识别和定义领域模型的边界
   - 明确每个上下文中的通用语言(Ubiquitous Language)

2. **上下文映射(Context Mapping)**
   - 定义不同限界上下文之间的关系
   - 常见模式：合作关系、客户-供应商、遵奉者、防腐层、开放主机服务、发布语言、分离方式等

3. **核心子域识别**
   - 区分核心域(Core Domain)、支撑子域(Supporting Subdomain)和通用子域(Generic Subdomain)
   - 决定资源分配和投资重点

4. **大比例结构(Large-Scale Structure)**
   - 为整个系统提供高层次的组织原则
   - 如分层架构、系统隐喻等

## 战术设计(Tactical Design)

战术设计关注的是在限界上下文内部如何实现模型，主要解决"如何构建领域模型"的问题：

1. **领域模型构建块**
   - 实体(Entity)：具有唯一标识的对象
   - 值对象(Value Object)：通过属性定义的对象
   - 聚合(Aggregate)：定义事务边界和一致性边界
   - 聚合根(Aggregate Root)：访问聚合的唯一入口

2. **领域服务(Domain Service)**
   - 处理不适合放在实体或值对象中的领域逻辑

3. **领域事件(Domain Event)**
   - 记录领域中发生的重要事情
   - 支持事件驱动架构

4. **仓储(Repository)**
   - 提供聚合的持久化和检索机制
   - 隔离领域模型与数据访问细节

5. **工厂(Factory)**
   - 封装复杂对象的创建逻辑

6. **应用服务(Application Service)**
   - 协调领域对象完成用例
   - 处理事务和安全等横切关注点

战略设计为系统提供宏观结构，而战术设计则提供了实现细节。两者相辅相成，共同构成了领域驱动设计的完整方法论。
